# on-demand-isr — where this repository stands

The entry page for anyone (or any agent) picking this repository up. It is
this repository's own state and does not ship to a site built from it; the
two pages that do are [operations.md](operations.md) and
[deployment.md](deployment.md).

## What it is

Vercel's On-Demand ISR template (vercel/on-demand-isr — a repository's GitHub
issues as statically generated pages, regenerated by a GitHub App's webhook
through `revalidatePath`) on Cloudflare Workers + Static Assets through
`@opennextjs/cloudflare`, its Next.js page and data cache in an R2 bucket and
two Durable Objects the Worker exports, packaged as an Orun baseline:
`orun new --blueprint repo-blueprint.yaml` builds a new site in its own
repository and takes it to live on stage and prod in one landing
(`01-product`) — the R2 bucket applied before the Worker that binds it — then
records what went live (`02-docs`). With no GitHub App connected `/` lists
sample issues and says how to connect one, and the webhook refuses every
delivery; the owner connects an App by setting its ID, private key and
webhook secret as Orun secrets and redeploying, and the site then lists its
own repository's issues. The Worker is about 1.3 MiB gzipped, so Workers Free
is enough.
